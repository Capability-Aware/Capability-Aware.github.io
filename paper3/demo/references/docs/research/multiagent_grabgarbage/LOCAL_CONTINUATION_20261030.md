# 前、后、腕视角共用的受控继续器

任务 `multiagent-grabgarbage`，分支 `feat/grab-garbage`。本轮已实现并完成 CPU 联通检查，**尚未接入实际运行器，也没有继承任一姿态的真实运动资格**。当前 v4 物理配对仍使用单独冻结的腕部路径；不将新接口重判到旧录像。

## 为什么需要统一

闭合被动实验结束时，前视仍有新定位，却因旧运行器只接受腕部续行而不能继续；这不是全部地面视角丢失。统一实现将“来源是否提供当前局部位置”和“方向、身体、预算是否允许移动”分别检查，使前视正向接近、后/腕视尾向接近使用相同守护。完整方法与 baseline 后续也必须共享相同姿态、低层控制器和证据等级配置，不能只给某一组纠偏能力。

## 新实现与调用顺序

新文件 [local_continuation.py](../../../source/capabilitylab/capabilitylab/cooperative/local_continuation.py) 提供 `LocalContinuationConfig`、`LocalContinuationSample`、`LocalContinuationExecutor` 与仅含身体请求的 `LocalContinuationCommand`。

1. 协调器用实际锚点建立一份 [ContinuationBudget](CONTINUATION_BUDGET_20261030.md)。每个实际物理帧只更新一次；移动、停稳和普通等待共扣12s，显式长观察共扣30s，所有实际XY折线共用0.5m。换相机、方向或继续器分段不能重建 owner。此合同针对单次受控近距交互；全场导航、多个垃圾和整场任务仍需各自明确的更高层预算。
2. 感知边界逐曝光更新 [LocalMotionEvidenceBridge](LOCAL_MOTION_EVIDENCE_20261030.md)，再逐物理步提供当前上游结果和同次实际帧查询 `current_target`。人工首框连续跟踪与实验关联分级保留，缺失/负结果立即撤销；不能省略定位拒绝的 `observe_tracking` 登记，只向查询提供仍为 tracked 的 AOT 结果。
3. 使用实际命名关节、速度、接触和身体反馈更新 `HeldWristMotionGuard`。该类虽然沿用 wrist 名称，但固定的六臂目标可由显式 profile 提供；真实软/硬限位仍由运行器传入。不能直接让原越过软限位的 fold 姿态获得合法资格。
4. 新继续器消费同一预算 owner 的当前只读快照、当前局部目标及同拍持姿守护输出。它要求 frame/capture/now/实际位置完全对应，持姿命令同拍、目标六关节与 profile 一致，且分段首次实际静止。长观察预算相位不能用于发送接近请求。
5. `front` 模式只接受 front，身体 `vx>0`，误差为 `wrap(yaw−bearing)`；`tail` 模式只接受 rear/wrist，`vx<0`，误差为原尾向定义。路由或方向变更必须由协调器先停车、确认实际静止、设置新证据门禁，再建立使用同一预算的新分段。此执行器不会自行切源、转身或展开腕部。

三路共用0.95m表面距离、0.12rad朝向、0.15m/s线速度范数、0.5rad/s角速度范数、0.25rad倾角、0.30–0.85m根部净高、0.5s低速完成、原反馈/时限/路径/命令过期守护。新配置只允许收紧这些上限，不允许缩短完成保持或改写本版距离目标。可选航向与减速继续使用同一已有配置；是否启用必须在各组相同冻结。

## 复用原守护与完成态撤销

`tail_reverse.py` 只增加相机匹配、朝向误差和移动方向三个 protected hooks。其默认表达式保持原 wrist-only、尾向误差和负vx，旧守护顺序与阈值未改。新适配器直接消费 `LocalMotionTarget`，没有将其转换为 `GroundGraspTarget`，也没有把 front/rear 角色伪装为 wrist。底层配置保留历史 `wrist_camera_id` 字段，但新适配器实际来源以独立 `camera_id/camera_role` 为准，元数据明确注明。

首次达到距离和连续低速后保留完成事件；后续每一拍仍需当前新鲜证据、当前距离/朝向以及实际低速和持姿静止。独立审查真实 CPU 组合复现了一个旧完成态缓存问题：完成后实际速度0.10m/s或角速度0.20rad/s虽未触硬守护，仍会沿用 complete。新适配层已修复：此时输出 `post_completion_actual_standstill_lost`、锁存失败并保持零，保留原首次完成时刻。缺当前目标或当前几何越界也撤销当前完成资格。

视觉当前有效与身体失败可以同时成立，分别记录。固定姿态/接触失效、不同帧预算、预算耗尽和原身体守护均优先于继续移动。完成只是受控局部距离阶段，没有身份认证、抓取、避障全局证明或清理成功。

## CPU 验证与实际缺口

[组合测试](../../../tests/cooperative/test_local_continuation.py) 使用实际 `OnlineTrackingWorker`、RGB-D定位、证据账本、预算 owner、固定姿态守护和新继续器。仅分割 backend 用合成 mask，反馈为CPU合成输入；它不构成神经识别或物理运动验收。

覆盖三路相机与正负方向、减速符号恢复、实际位姿进度、当前缺失后停车/新三帧恢复、不同帧预算拒绝、长观察相位拒绝、重建分段不能刷新共同预算、真实持姿/接触/身体拒绝、完成后当前视觉和低速撤销，以及不能放宽共同验收。新增组合测试为 **34 passed**；原实验/生产尾向联合回归也通过。证据账本53项、预算40项另有独立测试和文档。

全部模块初次合入后的 `tests/cooperative` 为1235项通过；随后加入原生观测sink和正常到点缓停候选，最终全套复验为 **1283 passed in 30.39 s**。这包含真实类型的组合与原默认行为回归，不代替实际四足姿态、神经感知或全任务资格。

后续仍需在实际运行器接入这个调用顺序，移除旧的一次前视恢复与 wrist-only 限制，分别实测合法 fold/front、rear/tail、展开 wrist/tail 的真实姿态、可见性、碰撞与移动。当前 rear 近地 FOV 不覆盖本夹具目标，不能通过换接口制造后视成功；前视重新初始化与自主同物关联也仍未完成。之后才能冻结公平完整算法比较，单垃圾抓取投放及全图异构协同目标保持不变。
